# Release Notes

## Unreleased

### dns-controller

* First version (phase C1 skeleton, not yet released): configuration from the environment with fail-fast validation, JSON-lines logging, `/healthz` and `/readyz`, a dependency-free Kubernetes REST client using the pod's ServiceAccount token and the cluster CA, a Lease-based single writer, and the versioned internal API (`dns.rapidmx.io/v1`) with the start-up compatibility handshake: on a version mismatch the controller refuses to act and reports it. It does not manage external-dns yet.
* Phase C2: the controller reads the server's desired state (`GET /v1/desired-state`, then a long poll on its version, treating any other version as a change) and reports its status (`PUT /v1/status`, after every new version and every minute, saying whether it holds the Lease). A malformed desired state is refused whole and never acted on; a server that no longer speaks `dns.rapidmx.io/v1` sends the controller back to the handshake. The controller serves no API of its own: only the health port (8081) listens, on IPv6 as well as IPv4, so a single-stack IPv6 cluster reaches it. New settings: `DNS_CONTROLLER_LONG_POLL_TIMEOUT_SECONDS` and `DNS_CONTROLLER_STATUS_INTERVAL_SECONDS`.
* Phase C3 (reconcile, first part): the controller turns the desired state into the namespace's objects with server-side apply: per DNS provider config one external-dns v0.23.0 Deployment (the pinned image only, one replica, none while the config is disabled or its credentials are incomplete, `Recreate`, hardened like the controller) reading only the `DNSEndpoint`s labelled for it, with its credentials only from the provider's Secret, which the controller writes from the credentials the server sends it (`GET /v1/providers/<uid>/credentials`) whenever the Secret is missing, holds another generation than the config's or is owned by a Deployment that is gone: labelled, annotated with its generation, owned by the Deployment, with Azure's `azure.json` built by the controller, and left as it is, with the pod, when the fetch fails or a field can't be decrypted; and per domain and per provider's hosts one `DNSEndpoint`, TXT targets in the form each provider keeps them (quoted, long values split into 255-byte strings, for Cloudflare, Route 53 and Google; verbatim for Azure, where a TXT name of several values is left out; unquoted for rfc2136, where a value with a space, `;` or quote is left out, since external-dns can't update or delete it there). An instance is kept out of zones another config has nested under its own; a state with a provider without zones, a zone in two configs, or a credential field name that isn't plain is refused whole. A new credentials generation rolls the pod once the Secret holds it. What the state no longer has is deleted; a deleted provider's instance goes one interval after its endpoints, so it can remove the records it owns. It writes only while compatible and holding the Lease, finishes the request under way before releasing the Lease on shutdown, and reconciles on every new state, when it takes the Lease and every 10 minutes. New settings: `DNS_CONTROLLER_FULLNAME` and `DNS_CONTROLLER_RELEASE` (required), `DNS_CONTROLLER_EXTERNAL_DNS_IMAGE`, `DNS_CONTROLLER_EXTERNAL_DNS_SERVICE_ACCOUNT`, `DNS_CONTROLLER_EXTERNAL_DNS_RESOURCES`, and `DNS_CONTROLLER_RESYNC_MINUTES`. Its Role needs `get`, `create`, `update`, `patch` and `delete` on Secrets (it reads their metadata only, never their values) and no `ExternalSecret` rights; a chart that still sets the OpenBao or External Secrets variables of the earlier build is not refused, they are ignored.
* Phase C3 (status): the Lease holder's status report now lists each provider's external-dns instance (ready replicas of its Deployment, the image it runs, when it last rolled out, reported only for a rollout that completed), each endpoint set's `DNSEndpoint` (the generation applied and the one external-dns has observed) and the result of each operation the desired state lists, read with one list of Deployments and one of `DNSEndpoint`s (no new rights). `lastRolloutAt` is a new optional field of the v1 provider entry; a server that does not know it leaves it out. A report also goes out when each reconcile pass ends. A pod without the Lease reports only itself.
* Phase C4 (operations): the controller runs the operations the server queues as one-shot Jobs from the pinned external-dns image with the provider's credentials, and reports each one's result in its status report. A **credentials test** is a dry run (`--dry-run --once`) that lists the zones. A **takeover** (`--registry=noop --policy=upsert-only --once`) writes the operation's records and the TXT registry's ownership record for each from a temporary `DNSEndpoint`, so the regular instance then owns them; it waits until the regular endpoint holds those records. A **restore** writes only the published SPF and the kept values, with no ownership record, once the regular instance (running, and having read the endpoint without the set) has removed the set. An operation waits for the provider's credentials Secret, is reported running with what it waits for, and fails with the last error external-dns logged. The Job is kept until the server stops listing the operation (it has no TTL), so a restart reads its result. Its Role needs `create`, `list`, `get` and `delete` on Jobs, `get` and `list` on pods (to read why a Job failed) and no new setting.
* Published as the container image `ghcr.io/rapidmx/dns-controller`, built on a distroless, non-root Node.js 24 base with no run-time dependencies. The RapidMX server's Helm chart deploys it and pins its version.
