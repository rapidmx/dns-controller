# Release Notes

## Unreleased

### dns-controller

* First version (phase C1 skeleton, not yet released): configuration from the environment with fail-fast validation, JSON-lines logging, `/healthz` and `/readyz`, a dependency-free Kubernetes REST client using the pod's ServiceAccount token and the cluster CA, a Lease-based single writer, and the versioned internal API (`dns.rapidmx.io/v1`) with the start-up compatibility handshake: on a version mismatch the controller refuses to act and reports it. It does not manage external-dns yet.
* Phase C2: the controller reads the server's desired state (`GET /v1/desired-state`, then a long poll on its version, treating any other version as a change) and reports its status (`PUT /v1/status`, after every new version and every minute, saying whether it holds the Lease). A malformed desired state is refused whole and never acted on; a server that no longer speaks `dns.rapidmx.io/v1` sends the controller back to the handshake. Its internal API (port 8080) accepts only the server's projected ServiceAccount token, verified against the cluster's keys fetched in-cluster, and serves nothing while the controller may not write. Both ports listen on IPv6 as well as IPv4, so a single-stack IPv6 cluster reaches them. New settings: `DNS_CONTROLLER_SERVER_SUBJECT` (required), `DNS_CONTROLLER_API_PORT`, `DNS_CONTROLLER_API_AUDIENCE`, `DNS_CONTROLLER_LONG_POLL_TIMEOUT_SECONDS` and `DNS_CONTROLLER_STATUS_INTERVAL_SECONDS`.
* Phase C3 (reconcile, first part): the controller turns the desired state into the namespace's objects with server-side apply: per DNS provider config one external-dns v0.23.0 Deployment (the pinned image only, one replica, none while the config is disabled or its credentials are incomplete, `Recreate`, hardened like the controller) reading only the `DNSEndpoint`s labelled for it, with its credentials only from the provider's Secret, which an `ExternalSecret` materializes when they are in OpenBao; and per domain and per provider's hosts one `DNSEndpoint`, TXT targets in the form each provider keeps them (quoted, long values split into 255-byte strings, for Cloudflare, Route 53 and Google; verbatim for Azure, where a TXT name of several values is left out; unquoted for rfc2136, where a value with a space, `;` or quote is left out, since external-dns can't update or delete it there). An instance is kept out of zones another config has nested under its own; a state with a provider without zones, a zone in two configs, or a credentials path outside `dns/` is refused whole. A new credentials generation rolls the pod once the Secret holds it. What the state no longer has is deleted; a deleted provider's instance goes one interval after its endpoints, so it can remove the records it owns. It writes only while compatible and holding the Lease, finishes the request under way before releasing the Lease on shutdown, and reconciles on every new state, when it takes the Lease and every 10 minutes. New settings: `DNS_CONTROLLER_FULLNAME` and `DNS_CONTROLLER_RELEASE` (required), `DNS_CONTROLLER_EXTERNAL_DNS_IMAGE`, `DNS_CONTROLLER_EXTERNAL_DNS_SERVICE_ACCOUNT`, `DNS_CONTROLLER_EXTERNAL_DNS_RESOURCES`, `DNS_CONTROLLER_RESYNC_MINUTES`, `DNS_CONTROLLER_OPENBAO_SECRET_STORE`, `DNS_CONTROLLER_OPENBAO_PATH_PREFIX` and `DNS_CONTROLLER_EXTERNAL_SECRETS_API_VERSION`. Its Role needs `get` on Secrets (it reads their metadata only, never their values).
* Published as the container image `ghcr.io/rapidmx/dns-controller`, built on a distroless, non-root Node.js 24 base with no run-time dependencies. The RapidMX server's Helm chart deploys it and pins its version.
